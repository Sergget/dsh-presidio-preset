## 1. CLI 产物会落明文（设计如此）

### 风险来源

`presidio_pii/cli.py` 的 `redact` 在写出脱敏文件的同时，会生成两个伴生文件：

| 文件 | 内容 | 是否明文 |
|---|---|---|
| `<out>.mapping.csv` | 占位符 ↔ **原文** 的完整对应关系 | **是** |
| `<out>.session.csv` | `session_id` / `doc_id` / 源路径 | 是（元数据） |

这是产物级可逆脱敏的必需载体：`restore` **优先**读 `mapping.csv`（见 `cli.py:12`），
因此只要脱敏目录整体拷走，就能在被拷贝的机器上无损还原。CLI 的设计目标正是「脱离
DSH 也能往返」，这个能力与「明文映射落地」是同一件事的两面。

对比：DSH 插件路径（`presidio_pii/server.py` + `sessions.db`）把映射存在 SQLite 里，
且已做文件权限加固（见第 3 节），不产生 CSV 明文。

### 当前缓解

- `restore` 的 `--session` 分支优先走映射库；CSV 只在没有会话库时作为回退。
- 门禁 #11「仓库不落真实 PII」会阻断 `*.mapping.csv` / `*.session.csv` 进入版本库。
- 归一体积：映射文件随产物目录走，不额外散落。

### 残余风险

- **任何人拿到 `<out>.mapping.csv` 就等于拿到原文**。把脱敏文件发给外部（尤其是连同
  目录一起打包）时，明文映射会一起泄露，脱敏完全失效。
- 云盘/邮件附件自动同步会把伴生文件一起上传。
- 映射文件不带加密，也不带访问控制。

### 使用前提（必须遵守）

1. **对外分发只用脱敏后的正文文件**，不要连 `.mapping.csv` / `.session.csv` 一起发。
2. 需要把整个目录交出去时，先删伴生文件，或改用 DSH 插件路径（映射在 `sessions.db`）。
3. 把 `*.mapping.csv`、`*.session.csv` 加进自己的 `.gitignore`（本仓库已加）。

## 2. 代码规则文件以 `import` 方式执行（能力即风险）

### 风险来源

`presidio_pii/custom_rules.py:234-255` 的 `_import_path()` 用
`importlib.util.spec_from_file_location` + `spec.loader.exec_module(mod)` 加载 `.py`
规则文件。**加载即执行**：模块顶层代码会在引擎初始化时运行，拥有当前进程的全部权限
（读文件、发网络请求、改环境变量……）。

同一个加载器也被 `_resolve_validator()`（`custom_rules.py:220-231`）复用，用来解析
`"模块路径:函数名"` 形式的校验函数引用。

### 为什么保留

这是「让用户写复杂校验逻辑」的唯一实现方式。JSON 规则只能表达正则模板；
需要按上下文判断（例如排除名单里的泛称、校验校验位）时，只能是代码。把 `.py` 换成
受限 DSL 会显著削弱表达能力，而受限 DSL 本身也要面对绕过问题。

### 当前缓解

- 只从**显式配置**加载：环境变量 `PII_DSH_CUSTOM_RULES`，或 preset.json 的
  `config.custom_rules_path`。不扫描目录、不自动发现、不从网络拉取。
- 环境变量走宽松模式（加载失败只告警不崩），`--rules` 显式传入走 strict 模式。
- 规则文件位于仓库/配置目录，受正常的文件系统权限保护，普通用户改不了。

### 残余风险

- **能改规则文件的人 = 能在 DSH 进程里执行任意代码的人**。这不是提权漏洞（改文件的人
  本来就有该权限），但它把「配置权限」和「代码执行权限」画上了等号。
- 多用户/共享目录场景下，如果规则文件可被低权限用户写入，就构成了提权路径。
- 代码规则异常会被 `load_code_rules` 捕获并降级（宽松模式），但**加载期副作用无法回滚**。

### 使用前提（必须遵守）

1. 规则文件目录的写权限**只给可信用户**；共享环境必须收紧 ACL。
2. 不要从他人手里接收 `.py` 规则文件后直接丢进 `custom_rules_path`——先读代码。
3. 只需要正则屏蔽词时，用设置页（`USER_TERM`）或 JSON 规则，不要引入 `.py`。

## 3. 本地映射库与日志的落地形态

| 载体 | 路径 | 内容 | 保护 |
|---|---|---|---|
| 会话映射库 | `.pii_presidio_store/sessions.db` | 占位符 ↔ 原文，**明文** | `icacls /inheritance:r`，仅当前用户 + SYSTEM + Administrators（POSIX 走 0700/0600） |
| 规则热更新日志 | `.pii_presidio_store/hook_log.jsonl` | 事件元数据 + 脱敏文本指纹 | 指纹为 **HMAC-SHA256**（密钥 `journal_hmac.key`，0600），非裸 SHA256，无法离线反查短 PII |
| 屏蔽词规则 | `.pii_presidio_store/user_terms_rules.json` | 用户填的屏蔽词，明文 | 依赖文件系统权限 |
| 白名单 | `config.whitelist_path` 指定的文件 | 不脱敏的词，明文 | 依赖文件系统权限 |

### 残余风险

- `sessions.db` 与规则文件**都是明文**——它们必须能被引擎直接读取，加密会引入密钥管理
  问题并把故障面扩大到「密钥丢了 = 历史映射全废」。保护手段是文件系统 ACL，不是加密。
- ACL 加固在 Windows 上依赖 `icacls`；命令失败只告警不阻断，因此**加固失败时库仍可读**。
  发布前应验证一次实际 ACL（`icacls <db>` 只应列出三个主体）。
- 备份/同步工具若以管理员身份运行，会绕过用户级 ACL。

### 使用前提

1. `.pii_presidio_store/` 及其内容**不得进入**版本库、打包制品、云同步目录。
2. 共享机器上不要把 `$DSH_HOME` 放在所有人可读的位置。
3. 迁移机器时，`sessions.db` 与 `journal_hmac.key` 需一并处理——只带 db 会导致旧指纹
   无法比对（不影响脱敏与还原，只影响日志一致性）。

## 4. 配置损坏时的降级方向（fail-safe 而非 fail-open）

`preset.json` 是运行时活配置：设置页保存的实体类型勾选（顶层 `entity_types`）与白名单
路径（`config.whitelist_path`）都从这里读，改完不重启 DSH 也生效（按 `mtime_ns + size`
签名热更新）。**配置读不出来时往哪个方向降级，是有安全含义的选择**——这里刻意分成
两个场景，都往「多脱敏」方向走：

| 场景 | 行为 | 为什么这样选 |
|---|---|---|
| 进程首次加载时 preset 损坏 | 回退到**全部 13 类启用**，stderr 告警 | 此时没有任何「上一次好配置」可继承；全部启用 = 最大脱敏覆盖，不会漏脱敏 |
| 运行中热更新时 preset 损坏 | **保留旧值不动**，stderr 告警一次 | 用户可能已把 13 类收窄成 2 类；重置成全开等于静默扩大脱敏面，收窄的意图丢失 |

实现上靠 `PresetUnreadable` 异常把「字段缺失」和「读不出来」分开：字段缺失是合法的
「全部启用」，读不出来是异常状态，必须由调用方决定降级方向，不能由 `_entity_types()`
自己静默返回空列表冒充前者。

签名（`mtime_ns + size`）在读取失败时仍然推进，避免坏状态每次调用都刷日志；用户修好
文件后签名变化会再次触发重载。

### 残余风险

- 损坏期间用户改了别的字段（比如屏蔽词路径），要等下次修好 preset 才会被应用。
- 「全部启用」包含 `PERSON`/`LOCATION`/`ORGANIZATION`，在中文文本上召回偏高，会
  产生较多占位符——这是刻意的过度脱敏，不是精度回归。
- 环境变量 `PII_DSH_ENTITY_TYPES` 优先于 preset，损坏 preset 不影响环境变量路径。

## 5. 已知盲区（不构成缺陷，但要知道）

| 盲区 | 说明 | 参考 |
|---|---|---|
| base64 / UTF-16 / 图片内文字 | 编码后的 PII 不识别；图片文字不 OCR | [DECISION-shell-redaction.md](DECISION-shell-redaction.md) §3 |
| shell 参数不做写入侧还原 | 写侧还原只覆盖 `write`/`edit`/`apply_patch`/`str_replace_editor` 的参数；把占位符传进 shell 命令不会被还原 | 插件 `WRITE_TOOLS` 常量 |
| bash 同构 | 本机无 bash，未验证 | 门禁 #5 |
| 自定义规则类型不受白名单约束 | `USER_TERM` 等自定义类型始终启用，勾选列表管不到 | `engine.py _filter_entity_types` |
| 文本指纹可关联 | 同一段 PII 在同一密钥下指纹稳定，可用于关联分析 | 见第 3 节 |
