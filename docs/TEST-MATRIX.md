# 测试面扩展研究

记录当前覆盖边界、实测缺口，以及可扩展方向的价值/成本评估。

## 1. 现状

| 维度 | 已覆盖 |
|---|---|
| 文档类型 | 简历、合同、公文、报告、文献、工资表、通讯录（84 份合成语料） |
| 文件格式 | docx（段落/表格/页眉页脚/文本框）、xlsx、pptx（文本框/表格/备注）、md、txt |
| 实体类型 | ID_NUMBER、PHONE_NUMBER、EMAIL_ADDRESS、CREDIT_CODE、BANK_CARD、PERSON、LOCATION、ORGANIZATION、JOB_TITLE |
| 评估 | 2409 条真值，按实体类型 × 文档类型统计召回与额外命中 |

## 2. 实测缺口（2026-10-29 首测，2026-10-31 复测）

用当前引擎直接跑变体与新增实体：

| 用例 | 首测结果（10-29） | 复测结果（10-31） |
|---|---|---|
| 全角数字 `１３８００１３８０００` | **未命中** | ✅ PHONE_NUMBER，还原无损 |
| 空格插值 `138 0013 8000` | **未命中** | ✅ PHONE_NUMBER，还原无损 |
| 换行截断 `11010119900307\n7890` | 部分命中，误判为 BANK_CARD | ✅ ID_NUMBER，还原无损 |

| 繁体姓名 `張偉` | **未命中** | ✅ PERSON，还原无损 |
| 英文姓名 `Zhang Wei` / 拼音 | **未命中** | ❌ 仍未命中（规则难做，属 NER 范畴） |
| 旧版 15 位身份证 | 命中但**类型错误**（BANK_CARD） | ✅ ID_NUMBER |
| 护照号 `E12345678` | **未命中** | ✅ PASSPORT |

## 3. 扩展维度矩阵

价值 = 对真实场景的覆盖提升；成本 = 实现+测试工作量。

### A. 实体类型

| 项 | 价值 | 成本 | 依赖 | 备注 |
|---|---|---|---|---|
| 15 位旧身份证 | 高 | 低 | 无 | 与银行卡冲突，需优先级+校验 |
| 护照 / 港澳台通行证 | 高 | 低 | 无 | 格式固定，易做 |
| 车牌号 | 中 | 低 | 无 | 省份简称 + 字母数字，误报可控 |
| IP / MAC | 中 | 低 | 无 | 日志、工单场景常见 |
| 银行卡 Luhn 校验 | 高 | 低 | 无 | 现在 13-19 位数字全判 BANK_CARD，误报源 |
| 组织机构代码 / 纳税人识别号 | 中 | 低 | 无 | 与统一社会信用代码并存 |
| 快递单号 / 订单号 / 工号 | 中 | 中 | 上下文词 | 纯数字，需前后关键词 |
| 社保号 / 公积金号 | 中 | 中 | 地区规则 | 各地格式不一 |
| 微信 / QQ / 支付宝账号 | 中 | 中 | 上下文词 | 形态与普通串难区分 |
| 出生日期 / 民族 / 学历 | 低 | 低 | 无 | 属个人属性，非标识符 |

## 4. 建议路线（按投入产出）

### P0 — 立即可做（约 1 天）

1. **文本归一化层**：NFKC（全角→半角）+ 插值去除，识别在归一化文本上做，回填用偏移映射
2. **实体补齐**：15 位身份证、护照、车牌、IP/MAC；银行卡加 Luhn
3. **文本格式 handler**：csv / json / xml / html / eml / rtf
4. **对抗用例集**：把本文第 2 节的 13 条变体固化为测试用例

### P1 — 短期（2–3 天）

5. **PDF 文本层只读模式**：识别 + 报告，不写回；明确标注"仅检测"
6. **docx 批注 / 修订 / 脚注 / 超链接**
7. **xlsx 批注与隐藏工作表**
8. **跨结构实体**：同一姓名被拆到多个 run 时先合并再识别

### P2 — 中期（1 周+）

9. **OCR 通道**：tesseract 或 paddleocr，单独依赖与单独精度口径
10. **旧版 .doc/.xls**：`antiword` 只读；写回不可行
11. **人工真值集**：200–500 句，双人标注，作为最终验收口径

### 不建议

- 无限增加同构合成文档（边际收益接近 0）
- 用 OCR 结果做"还原"（噪声不可逆）
- 在没有人工真值的情况下继续调阈值（会过拟合合成语料）

## 5. 关键判断

1. **格式变体 > 文档类型**：13 条变体里 10 条完全未命中，而新增文档类型只会重复验证已有能力。
2. **类型错误比漏检更隐蔽**：15 位身份证被判成 BANK_CARD，脱敏了但类型错，影响下游统计与还原策略。
3. **PDF/OCR 必须与主路径隔离**：不能写回，就不能伪装成普通 handler，否则 `restore` 语义会被破坏。
4. **人工真值是下一阶段的门槛**：合成语料能证明"能识别"，不能证明"在真实分布上够用"。

## 6. 实施结果（2026-10-30）

按第 4 节的 P0/P1/P2 路线实施，OCR 按决策跳过（tesseract 本体不可安装）。

### 测试

基线 60 passed → **85 passed**（新增 25 条）。

### 语料回归（无退化）

| 类型 | v2（2409 条） | v1（155 条） |
|---|---|---|
| ID / PHONE / EMAIL / CREDIT / BANK / PERSON / LOCATION / JOB_TITLE | 100% | 100% |
| ORGANIZATION | 99.3% | 98.8% |
| 简称（hard） | 97.2% | 95.8% |

### 实施中发现并修复的问题

1. 归一化把 `.` 当分隔符吞掉 → IPv4 与邮箱全部失效
2. ASCII 连字符 `-` 不在分隔符集合 → `138-0013-8000` 漏检
3. IPv4 正则前后瞻写错 → IP 完全不命中
4. `共三部` 被判成 ORGANIZATION（数量表达未排除）
5. xml 同名标签键重复 → 回填互相覆盖
6. openpyxl 的 `ws._comments` 不填充，批注实际挂在 `cell.comment`
7. **语料生成器 Luhn 实现有误**（校验位也乘了 2），加校验后 BANK_CARD 召回 100%→9.1%，修的是生成器不是识别器

### 遗留

- 无机构后缀的简称（「中科云谷」）仍需别名表或 NER
- 英文姓名 / 拼音未支持（规则难做，属 NER 范畴）
- 简繁转换仅覆盖姓氏，未做全文本转换
- OCR 通道未实施（tesseract 不可安装）
- 人工真值集数据待标注（`truthset/annotations.jsonl` 已生成 276 条空模板）

## 7. 增量结果（2026-10-31）

### 产出

| 文件 | 内容 |
|---|---|
| `presidio_pii/custom_rules.py` | 自定义识别规则：JSON 正则模板 + Python 代码规则，含 context/negative hint、validator、异常隔离、严格/宽松两种加载模式 |
| `presidio_pii/hooks.py` | 直接读取 preset.json 的 `config` 段，优先级 环境变量 > preset > 默认 |
| `presidio_pii/cli.py` | `--rules` 入口；显式规则严格加载，失败非零退出 |
| `tests/test_custom_rules.py` | 20 条用例：Luhn 降级、正则/代码模板、严格模式、preset 注入、白名单联动、CLI 与 docx 端到端 |

### 测试

105 passed（上一轮 85 → 新增 20 条）。

### 语料回归（无退化）

| 指标 | 结果 |
|---|---|
| v2 召回（2409 条） | 2408/2409 = 99.96% |
| 额外命中 | 73 条（与上一轮持平，未因 Luhn 降级上升） |

### 本轮修复

1. **银行卡 Luhn 失败裸漏**：19 位 Luhn 不通过的卡号此前完全未识别。现降级 0.45 保留；
   18 位身份证仍由 ID_NUMBER 优先仲裁（等长 + 优先级）。
2. **preset.json 配置未接线**：`custom_rules_path` / `whitelist_path` 此前只写不读，现由 hooks 实际加载。
3. **规则加载失败静默放行**：显式指定规则缺失时曾以 0 退出并输出原文，现非零退出。
4. **代码规则异常中断流水线**：规则返回 `None` 或抛异常会击穿整个脱敏，现单规则隔离。
5. **validator 相对路径**：原按 cwd 解析且异常未捕获，现按规则文件目录解析。

### 更新后的关键判断

1. 格式变体缺口已基本闭合（11/12），**英文姓名/拼音是唯一遗留**，属 NER 范畴，规则层不建议硬做。
2. 自定义规则把「新实体类型」的成本从改引擎降为写配置，但**规则文件是可信边界**：
   代码规则 import 即执行，需与配置同等保护。
3. 规则层的新风险是**静默失效**（文件缺失、规则全非法），因此显式来源必须严格加载。
4. 人工真值仍是下一阶段门槛；合成语料无法证明真实分布下的可用性。
