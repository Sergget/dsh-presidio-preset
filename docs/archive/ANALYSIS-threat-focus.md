# 谁在对抗谁：两份研究里 26 条问题的价值重排

> 前提（用户口径）：本项目的主要目的是**防止大模型不受控地获取本地敏感信息字段**——内容里的姓名、年龄、职务、身份证号等。
>
> 本文只回答一个问题：前面两份报告里的 26 条问题（+ 6 条硬否定），各自在对抗**谁**；哪些其实与这个目的无关。

---

## 0. 一句话结论

**大部分篇幅花在了「对抗本地工具环境」上，而真正该被对抗的对象是模型。更严重的是：用户点名的「年龄」，引擎零覆盖——这条最重要的缺口，两份报告一个字都没提。**

分类结果（26 条，逐条对得上）：

| 类别 | 条目 | 占比 | 是否服务于目标 |
|---|---:|---:|---|
| ① 对抗本地工具/环境（Windows 沙箱、host 平面、插件机制） | 11 | 42% | 只有 3 条是必经之路，其余是环境噪音 |
| ② 在文件名/路径这类可接受暴露上较劲 | 2 | 8% | 建议整类降级 |
| ③ 对抗模型（模型能看到什么、能拿到什么） | 7 | 27% | **主战场** |
| ④ 与目标无关（格式保真、产品取舍） | 6 | 23% | 该做，但不该占安全论证的篇幅 |

逐条归属见 §2–§5，26 条全部有位置，不重不漏。

---

## 1. 判据

一条问题算「服务于目标」，当且仅当：**解决它能减少「模型上下文里出现的内容字段原文」**。

用这把尺子量，以下三类都不算：

- 沙箱能不能限制读 —— 只要工具面里没有读通道，沙箱管不管读**不改变模型看到什么**；
- 路径、文件名是否被脱敏 —— 路径里有姓名属于边角，且模型拿到路径**不等于**拿到字段；
- 插件机制摩擦（`restrict` 是运行期 API、未知名抛错、KV cache 失效）—— 是实现成本，不是安全边界。

---

## 2. ① 对抗本地工具/环境（11 条）

| ID | 问题 | 为什么算这一类 | 要不要做 |
|---|---|---|---|
| P0-1 | 「禁止 bash 读文件」不可实现（Windows 沙箱只管写） | 对抗的是操作系统 ACL 能力 | **不做**——删 shell，绕开这个战场 |
| P0-2 | 白名单/命令判别安全收益低 | 对抗的是「命令文本能否被可靠解析」 | **不做**——同上，删 shell 后消失 |
| P0-5 | host 平面三条（`spill-local`/`spill-policy`/`session-persistence-jsonl`）preset 管不到 | 对抗的是 DSH 分层组合结构 | **必须做**——它们是原文落盘点 |
| P0-7 | spill 把原文写进磁盘 + 两个 `prepend` 监听器顺序不稳 | 对抗插件注册顺序 | **必须做**——自建工具限长即可绕开 |
| P1-1 | `restrict` 是运行期 API，不能配在 yml | 插件机制摩擦 | 做（一次性成本） |
| P1-2 | `restrict` 命名未知工具直接抛错 | 插件机制摩擦 | 做（加 try/catch） |
| P1-3 | `restrict` 不能命名 `run_code` | 插件机制摩擦 | 做（restrict 底层工具） |
| P1-4 | `restrict` 变更会 invalidate KV cache | 性能，与安全无关 | 知道即可，不写进契约 |
| P1-5 | `tool-fs-search` 无单工具开关 | 插件设计 | **不做**——web-app 层已 disabled，不写就没有 |
| P1-7 | 会话 JSONL 明文（zstd 非加密） | 对抗文件系统权限 | 文档明写即可，别当安全项 |
| P1-9 | 写入侧 tool/call 落盘的是占位符版参数，审计看不出真实写入 | 审计完整性，不是防泄漏 | 可延后 |

> **这一类的正确姿态**：P0-1 / P0-2 / P1-5 三条殊途同归——**别在环境层做对抗，直接在工具面把通道删掉**。删了 `bash`/`read`/`grep` 之后，这 11 条里有 4 条自动消失（P0-1、P0-2、P1-5，以及 P1-7 的紧迫性大幅下降）。

## 3. ② 在文件名/路径上较劲（2 条）

| ID | 问题 | 为什么算这一类 | 建议 |
|---|---|---|---|
| P0-3 | `isError` 不可脱敏，而 fs 层 57 处错误里 39 处内嵌 `displayPath` | 泄漏的是**路径**，不是字段内容 | **降级为 P2**：自建工具内部 catch 抹路径即可，不去改第三方工具 |
| P2-7 | `present` 暴露源文件路径 | 同上 | 写入前把文件名改成占位符名，够了 |

**仓库自己早就判过这一题**：`docs/DECISION-shell-redaction.md` §4 误伤表把「路径被替换导致模型照抄路径报错环路」列为**接受**，理由是拼写错误的代价高于路径里那点信息。

→ 继续在这上面加防护，是**推翻自己的既有决策**，且收益接近零。

### 一个相关的实现事实（不计入 26 条）

`plugins/dsh-pii-guard/lib/index.js:190-196` 的 `redactExempted` 会把 shell 输出里「处在路径中」的 `ORGANIZATION` 占位符**还原成原文**（`:195` `if (!ph.includes("ORGANIZATION")) continue;`）。这是对路径类问题的**主动让步**——已经写在代码里了，方向与本类「降级」的建议一致。

## 4. ③ 对抗模型（7 条）——主战场

| ID | 问题 | 模型能拿到什么 | 优先级 |
|---|---|---|---|
| P0-4 | PTC `run_code` 给程序的是 canonical value，post-execute 对程序无效 | **原文全部** | P0 |
| P0-6 | 用户粘贴进输入框的文本在工具级守卫之外 | **原文全部** | P0（客户端问题，超出本方案） |
| P1-6 | `spill` 的 `retrievalHint` 主动教模型「用 read 或 grep 这个路径」 | **原文**（磁盘上就是原文） | P0——与 P0-7 同源，合并处理 |
| P1-8 | `failOpen` 开关存在，打开就变成「无保护工具面」 | **原文全部** | P0——极简预设里禁止，加门禁断言 |
| P1-10 | 占位符编号跨文档全局递增 → 还原时张冠李戴 | 不是原文，是**错位**：A 的身份证号写进 B 的行 | P1（合同/报表场景升 P0） |
| P2-5 | 自定义规则正则无超时，可 ReDoS | 不是泄漏，是可被拖死 | P2 |
| P2-6 | `read_image` 无法脱敏，已在 PII 预设内 deny | 图片内文字 | 已处理 |

**对应的三条硬否定**（不在 26 条内，但同属这一类）：
- 硬否定三：`grep` 直接返回 `Line N: <preview>` —— 原文片段，正是「删工具面」要解决的；
- 硬否定四：用户粘贴的文本 —— 同 P0-6；
- 硬否定五：占位符可被模型伪造（`⟦PII:PERSON:0001⟧` 可手写）—— 模型造不出原文，但能**错位搬运**，与 P1-10 同源。

> **这一类的共同点**：全部指向同一件事——**模型能看到的每一个通道都必须已经过脱敏，或者干脆不存在**。所谓「工具级钉死」，钉的就是这个。

## 6. 比这 26 条更要紧的：清单之外的两个真空

### 6.1 用户点名的「年龄」，引擎零覆盖（实测）

用 22 条字段探针跑现有引擎（`PresidioPIIEngine(db_path=":memory:")`）：

| 字段 | 探针句 | 结果 |
|---|---|---|
| 姓名（强上下文） | `由范志强负责本次审计。` | ✅ PERSON |
| 姓名（弱上下文） | `员工范志强，男，45岁。` | ❌ **漏** |
| **年龄** | `该同志年龄 45 周岁。` | ❌ **漏** |
| **年龄** | `年龄：38` | ❌ **漏** |
| **年龄** | `今年 40 岁。` / `现年 52 岁。` | ❌ **漏** |
| **出生日期** | `出生日期：1990-03-07` / `生于1985年12月。` | ❌ **漏** |
| **性别 / 民族** | `性别：男，民族：汉族。` | ❌ **漏** |
| **学历** | `学历：硕士研究生。` | ❌ **漏** |
| **微信 / 工号** | `微信：zhangsan_1985` / `工号：E123456` | ❌ **漏** |
| 职务 | `现任省发展与改革委员会副主任。` | ✅ JOB_TITLE |
| 身份证 / 手机 / 邮箱 / 银行卡 / 车牌 | — | ✅ |
| 住址 | `住址：北京市朝阳区建国路88号3单元501。` | ⚠️ 只到「3单元」，`501` 丢了 |

**合计 HIT=13 / MISS=9**，漏掉的正是用户点名的「年龄」。

`README.md:9` 的字段清单里本来就没有年龄/性别/民族/学历/出生日期——所以这不是 bug，是**需求真空**：产品的字段范围比用户刚说的目标窄。

**好消息（已实测）**：不需要改引擎，用现成的 `custom_rules` JSON 通道加一条即可，且 redact→restore 全链路无损：

```json
[{"name": "age-ctx", "entity_type": "AGE",
  "pattern": "\\d{1,3}(?=\\s?周?岁)", "score": 0.85, "priority": 5,
  "context_hint": ["年龄", "现年", "今年", "年方", "周岁"]}]
```
实测输出 `该同志年龄 ⟦PII:AGE:0001⟧ 周岁，现任⟦PII:JOB_TITLE:0001⟧。` → 还原无损 `True`。
`_PRIO` 里没有 `AGE` 也不影响（未声明类型兜底 99）。

**但有个坑必须先解决**（实测）：朴素写法 `\d{1,3}(?:岁|周岁)` 会误伤——
- `本项目…覆盖20岁以上人群` → 误判 `AGE: 20岁`
- `儿童用药：3岁以下禁用` → 误判 `AGE: 3岁`

这正是 `agent.md` §3「无边界不成实体」要防的。**年龄不能靠单位词判定，必须靠标签上下文**（`年龄/现年/今年`）或「标签+值」双形态，并复用 `_QUANTITY_PREFIX`（`共分设含计约由`）那类排除逻辑。

### 6.2 职务命中了，但边界是坏的（实测）

| 探针句 | 实际输出 | 问题 |
|---|---|---|
| `他是公司总经理。` | `ORGANIZATION: 他是公司` + `JOB_TITLE: 总经理` | 机构名把「他是」吞进去了 |
| `担任办公室主任一职。` | `ORGANIZATION: 担任办公室` + `JOB_TITLE: 主任` | 同上，吞了「担任」 |

机构名的左边界（`_trim_org_start` / `_ORG_PREFIX_WORDS`）没覆盖「代词+动词」开头。**这比任何路径问题都更贴近「模型拿到内容字段」**——它让模型看到了错的内容。

## 7. 建议的动作

**砍掉：**
- ② 整类（2 条）——降级为 P2，只剩「自建工具内部 catch 抹路径」一条真动作；
- P0-1 / P0-2 / P1-5——删掉 shell 与 `read`/`grep` 后自动消失；
- P1-4——性能问题，别写进安全契约。

**保留并前移：**
- 工具面最小化（删 `bash`/`read`/`write`/`edit`/`grep`，只留自建四件套）——一次性解决 ③ 里的 3 条；
- PTC 不装（`dsh-tool-executor-ptc` 在 base 里已 `disabled: true`，只需加门禁断言防止被打开）；
- spill 三件（host 平面）——真正的原文落盘点；
- `failOpen` 严禁在极简预设里打开（P1-8）。

**补上（这才是用户要的）：**
- 新增 `AGE` / `BIRTH_DATE` / `GENDER` / `ETHNICITY` / `EDUCATION` / `IM_ACCOUNT` / `EMPLOYEE_ID` 一类「人事字段」规则库——正好复用第一份报告的规则库化设计（每条一行、可开关、可自定义）；
- 修机构名左边界（`他是公司` / `担任办公室`）；
- 修住址尾号（`501` 丢失）；
- 补姓名弱上下文（`员工范志强`）。
